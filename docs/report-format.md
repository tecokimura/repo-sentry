# レポートフォーマット仕様（Phase 1: sentry-scan）

> **注意**: このドキュメントは **Phase 1（sentry-scan）** が直接生成する Markdown レポートの
> フォーマットを説明しています。
>
> **Phase 3（sentry-report）** のレポートフォーマット（エグゼクティブサマリー・計画対応項目・
> 修正ガイドなど）は [docs/phase.md](phase.md) の「Phase 3:
> sentry-report」セクションを参照してください。 sentry-report は `enriched_*.json` を入力として AI
> と Renderer が協調してレポートを生成します。

---

repo-sentry（sentry-scan）が生成する Markdown レポートのフォーマット定義。

Clearwing を使用しない場合はエンジニア向けの技術データ層として機能し、 Clearwing
を使用する場合は関係者への共有・意思決定に使えるドキュメントとして機能する。

---

## ドキュメント構成

```
1. ヘッダー（スキャン基本情報）
2. 対応優先度サマリー          ← 常に出力
3. Collector 実行結果          ← 常に出力
4. Findings（深刻度順）        ← 常に出力
   各 Finding 内:
     - 基本情報                ← 常に出力
     - 対応コマンド            ← 常に出力
     - リスク                  ← Clearwing のみ
     - 類似インシデント        ← Clearwing のみ
     - 対応判断メモ            ← Clearwing のみ
```

---

## フォーマット

### ヘッダー

```markdown
# repo-sentry Security Scan Report: owner/repo

Scan date: YYYY-MM-DD Clearwing: なし ← または "含む (depth: quick)"
```

---

### 対応優先度サマリー

Clearwing の有無にかかわらず深刻度から機械的に生成する。
見る人が意思決定・上申の判断材料として使うことを想定。

```markdown
## 対応優先度サマリー

| 優先度                    | 件数 | 主なリスク                  | 推奨期限  |
| ------------------------- | ---- | --------------------------- | --------- |
| 今すぐ対応 (Critical)     | 1    | サーバー上でのコマンド実行  | 今週中    |
| 優先対応 (High)           | 6    | 情報漏洩・メール改ざん・DoS | 2週間以内 |
| 計画的に対応 (Medium/Low) | 21   | XSS・なりすまし・設定不備   | 1ヶ月以内 |
```

---

### Collector 実行結果

```markdown
## Collector 実行結果

| ツール   | 状態 | 検出数 | 備考             |
| -------- | ---- | -----: | ---------------- |
| gitleaks | 完了 |      0 | 認証情報漏洩なし |
| trivy    | 完了 |     28 |                  |
```

---

### Findings

深刻度の高い順（Critical → High → Medium → Low → Unknown）に出力する。
同一深刻度内はパッケージ名順。

#### Finding 単位のフォーマット（Clearwing なし）

```markdown
### [CRITICAL] タイトル

**CVE-XXXX-XXXXX** · パッケージ名 · 場所（composer.lock 等）

|                    |             |
| ------------------ | ----------- |
| 現在バージョン     | x.y.z       |
| 推奨対応バージョン | x.y.z 以上  |
| 参考               | https://... |

**対応コマンド** `composer require パッケージ名:"^x.y.z"`
```

#### Finding 単位のフォーマット（Clearwing あり）

上記の基本情報・対応コマンドに加えて以下を追記する。

```markdown
#### リスク

このコードベースにおける脆弱性の到達可能性と、
攻撃が成立した場合の具体的な影響をビジネス視点で記述する。 汎用的な CVE
説明ではなく、このリポジトリ固有の文脈で記述すること。

#### 類似インシデント

実際に発生した類似の攻撃・被害事例へのリンクと概要。
信頼できる情報源（CISA・NVD・報道機関等）に限定する。

#### 対応判断メモ

- **影響範囲:** 本番環境への影響が限定される条件があれば記載
- **対応コスト:** 修正に必要な作業量の目安
- **放置した場合:** 攻撃が成立した場合に起こりうる事象
```

---

## Clearwing あり・なしの対応関係

| セクション                  | Clearwing なし             | Clearwing あり                   |
| --------------------------- | -------------------------- | -------------------------------- |
| 対応優先度サマリー          | 出力（深刻度から自動生成） | 出力（Clearwing の再評価を反映） |
| 基本情報（バージョン・URL） | 出力                       | 出力                             |
| 対応コマンド                | 出力                       | 出力                             |
| リスク                      | **出力しない**             | 出力                             |
| 類似インシデント            | **出力しない**             | 出力                             |
| 対応判断メモ                | **出力しない**             | 出力                             |

Clearwing なし時は「リスク」「類似インシデント」「対応判断メモ」セクションを
省略する（空欄・プレースホルダーは出力しない）。

---

## 実装上の注意

- `fixedVersion` は Trivy の生出力から取得する（`Finding.raw.fixedVersion`）
- 深刻度順ソートは reporter 側で行う
- Clearwing セクションは Clearwing collector の出力として Finding に付加される
- 類似インシデントの URL は Clearwing が検索・選定する（ハードコードしない）
